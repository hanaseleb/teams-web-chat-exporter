# Ebi AI Console へ Teams / Slack 会話を送る

この拡張機能は、選択した Teams または Slack の会話を既存の書き出し形式で生成し、ダウンロードの代わりに relay の `POST /api/ingest` へ送ります。送信はバックグラウンドから行い、接続先と Ebi Ingest の Bearer トークンは拡張機能の `chrome.storage.local` に保存します。

## Relay 側の設定

Ingest は初期状態では無効です。relay の環境変数を設定して relay を再起動する必要があります。

| 環境変数 | 役割 |
|---|---|
| `CCDB_INGEST_TOKEN` | `POST /api/ingest` の Bearer 認証トークンです。`CCDB_API_SECRET` とは別の値です。未設定だと Ingest は `503` を返します。 |
| `CCDB_INGEST_HOST` | Ingest 専用リスナーのバインドアドレスです。 |
| `CCDB_INGEST_PORT` | Ingest 専用リスナーのポートです。`CCDB_INGEST_HOST` と両方を設定するとリスナーが起動します。 |

外部リスナーは Ingest 専用です。信頼できるネットワークからだけ到達できるアドレスにバインドし、インターネットへ無制限に公開しないでください。利用するアドレスとポートを拡張機能の URL に入力します。トークンは秘密情報として管理し、リポジトリやログに保存しないでください。

この機能を追加した時点では、この環境の relay は Ingest が無効で `503` を返します。拡張機能だけでは有効化されません。

## 拡張機能の設定

1. ビルドした拡張機能の設定画面を開き、**Ebi AI Console** を見つけます。
2. **Ingest API のベース URL** に relay の URL を入力します。末尾に `/api/ingest` は付けません。拡張機能がパスを追加します。
3. **Ingest API トークン** に `CCDB_INGEST_TOKEN` と同じ値を入力します。
4. **接続設定を保存** を押し、ブラウザーが表示する接続先ホストへのアクセス許可を与えます。

接続先は HTTP または HTTPS を指定できます。トークンは拡張機能のローカルストレージに保存され、Diagnostics のオプション一覧には含まれません。設定を保存すると、入力した接続先のオリジンだけを実行時に要求します。

## Teams Web から送る

1. Teams Web を開いて拡張機能のポップアップを表示します。
2. 会話ピッカーでチャネルの会話、チャット、または自分用メモのチャットを選択します。
3. 送信先の **Ebi Workspace のプロジェクト名**を入力します。過去に送った名前は候補に表示され、直近10件が拡張機能のローカルストレージに残ります。
4. 書き出し形式や日付範囲などを選択して **Ebi AI Console へ送る** を押します。

生成するファイルは既存の書き出しビルダーをそのまま使います。1会話・1形式ならそのファイルを送信し、複数形式または複数会話なら従来と同じ ZIP 1つを送信します。受信した側では ZIP が展開されます。Ingest への送信上限は base64 を含むリクエスト全体で50 MiBです。超える場合は送信前にエラーを表示します。

Teams の「ファイル添付」設定による SharePoint 文書の個別ダウンロード分は、この送信には含めません。会話書き出し内に含まれる画像や選択形式の出力は送信されます。

## Slack Web から送る

1. `https://app.slack.com/` にログインした状態で拡張機能のポップアップを開きます。
2. ピッカーには、ブラウザーでログイン中の各ワークスペースのチャンネル、DM、グループ DM が表示されます。行の補助表示でワークスペースを確認して、会話を選択します。
3. 会話を1件選ぶと、その履歴を調べてスレッドがある場合に `↳` で始まる行を追加します。追加された行から個別のスレッドを選ぶと、その親投稿と返信を書き出します。スレッドだけ送りたい場合は親会話の選択を外してください。履歴が長い場合は一覧追加に時間がかかります。
4. 必要なら「返信を含める」を有効にします。会話全体を選んだ場合は、各親投稿のスレッド返信も含まれます。無効なら個別スレッドの親投稿だけを書き出します。
5. Ebi Workspace のプロジェクト名を入力し、**Ebi AI Console へ送る** を押します。

Slack の会話も既存の JSON / CSV / HTML / TXT / PDF ビルダーで作成し、会話ごとの ZIP にまとめます。保存先は `<プロジェクト>/Slack Export/<ワークスペース名>/<会話名>/` です。

Slack Web のファイル添付は、「ファイル添付」設定が有効な場合に取得を試み、ZIP 内の `attachments/` に含めます。サイズ上限または設定で取得しないファイルは Ingest の `attachments_manifest` に `linked`、取得に失敗したファイルは `failed` として記録します。設定を無効にした場合もファイルのリンクはエクスポートに残ります。

Slack が API のレート制限を返した場合、拡張機能は `Retry-After` の秒数を待って再試行します。

Slack の資格情報は Slack Web ページ内でのみ一時的に読み取り、Slack API 呼び出しに使います。拡張機能のストレージ、Diagnostics、ログには保存・出力せず、Ebi Ingest へ送ることもありません。会話本文や添付ファイルは、選択後に設定済みの Ingest API へ送信されます。Slack Web のセッション形式は公開 API 契約ではないため、Slack が内部保存方法を変更すると一覧取得に失敗する場合があります。その場合は Slack Web のタブを再読み込みしてから再試行してください。

## Teams の保存先の決まり方

送信時に添付ファイルと一緒に保存指示を送り、受信した AI セッションに次の処理を依頼します。

- Ebi Workspace の `02_Contexts/<コンテキスト>/<プロジェクト>/` 以下から、入力されたプロジェクト名に合うフォルダを探す。
- 一意に特定できたら、その中の `Teams Export/<会話名>/` に各会話のファイルを保存する。
- 候補が複数、または一致するフォルダがなければ何も保存せず、ユーザーに確認する。
- ファイルの内容を要約・再構成・改変せず、保存後に実際のパスを報告する。

保存先を指定する Ingest API の専用フィールドはありません。この動作はリクエストの `content` に含める指示文で実現します。

## 拡張機能を読み込む

ソースを取得して依存関係を準備し、リポジトリのルートで次を実行します。

```bash
npx -y pnpm@10.23.0 install
npx -y pnpm@10.23.0 build
```

Chrome / Edge では `chrome://extensions` を開いてデベロッパーモードを有効にし、**パッケージ化されていない拡張機能を読み込む** から `.output/chrome-mv3/` を選択します。Firefox では `about:debugging#/runtime/this-firefox` を開き、**一時的なアドオンを読み込む** から `.output/firefox-mv2/manifest.json` を選択します。

## エラー

- `503`: relay 側で Ingest が無効です。relay 環境変数を確認してください。
- `401`: トークンが一致しません。
- `409`: サーバーが添付ファイルの欠落などを検出して送信を拒否しました。
- 接続エラー: URL、ホストアクセス許可、ネットワークを確認してください。
- サイズ超過: 選択範囲や形式を減らして再送してください。
